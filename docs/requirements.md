# 要件

## 状態と対象

2026-10-08 時点の設計仕様です。Phase 1 の最小 SDK プラグインを実装済みで、macOS の基本保存と元 RAW / XMP の内容不変についてユーザー報告があります。全体の技術検証は未完了です。Phase 2 の ExifTool 単体読取を追加しました。書き出しとの全体統合は未実装です。以下の「必須」は製品要件、「初期設計」は検証結果で調整できる実装方針を示します。

対象は Adobe Lightroom Classic のみ、Lua / Classic SDK、Windows / macOS。最低対応バージョン、CPU 構成、Lua バージョンは公式 SDK 確認後に決定します。ExifTool は配布物へ同梱します。クラウド版 Lightroom、動画、Publish Service、外部アップロードは対象外です。

## 機能要件

| ID | 必須の動作 |
| --- | --- |
| F-01 | Export Service Provider として書き出し画面に独自設定 UI を追加する。登録方法とフックは SDK で確認する。 |
| F-02 | ファイル名テンプレートを設定でき、未知トークン・不正構文を実行前に表示する。 |
| F-03 | 実行時と同じ解決・整形規則でプレビューを表示する。未確定の連番・衝突名はその旨を示す。 |
| F-04 | ExifTool で XMP / RAW / JPG を読み取り、項目単位で XMP → RAW → JPG の順にフォールバックする。 |
| F-05 | RAW 探索場所を「JPG と同階層」「JPG の 1 つ上」「同階層 → 1 つ上」から選択できる。RAF / DNG を最低限サポートする。 |
| F-06 | Date、Time、DateTime、Original、CameraMaker、Camera、LensMaker、Lens、FilmSim の 9 トークンを扱う。 |
| F-07 | メーカー重複省略を切り替えられる。比較は正規化後に行い、同一ならカメラメーカー側を残す。 |
| F-08 | C2PA / Content Credentials（JUMBF）削除を選択できる。削除対象は今回生成した書き出しファイルだけに制限する。 |
| F-09 | 指定出力フォルダへ生成名で保存し、衝突は別名化する。暗黙の上書きをしない。 |
| F-10 | エラー、キャンセル、処理件数を報告する。失敗した写真を成功扱いしない。 |

## 初期設計

- 最初の統合検証は JPEG 出力。他形式は保存・削除処理を検証するまで対応を約束しない。
- RAW 探索の初期値は「同階層 → 1 つ上」、メーカー重複省略は ON、C2PA 削除は OFF。
- テンプレート初期値は `{DateTime}_{Original}`。
- ファイル名だけをテンプレートで指定し、出力フォルダは別設定とする。
- 入力・設定を書き出し開始時に固定し、1 枚ずつ処理する。並列化、常駐 ExifTool、永続キャッシュは初期範囲に含めない。
- 詳細は [メタデータ](metadata-resolution.md)、[トークン](tokens.md)、[C2PA](c2pa.md) を正とする。

## 安全要件

| ID | 不変条件 |
| --- | --- |
| S-01 | 元 RAW、元 JPG、XMP、Lightroom カタログ内の元画像の内容を一切変更しない。 |
| S-02 | 既存の出力ファイルを暗黙に上書きしない。保存時点でも衝突を検出する。 |
| S-03 | 書き込み・削除・清掃はセッションで所有を記録した作業ファイルに限定する。元画像と同じ実体なら拒否する。 |
| S-04 | C2PA 削除は新規レンダリングから作った作業用コピーのみで行い、成功確認後に出力を確定する。 |
| S-05 | ExifTool 引数へユーザー文字列を無検証で連結しない。任意オプションやコード実行を許可しない。 |
| S-06 | 存在しない SDK API を推測しない。公式リファレンス・サンプルで根拠を確認する。 |

## 非機能要件と受け入れ条件

core は SDK、ExifTool、I/O なしで単体テストできる。外部処理にタイムアウトを設け、破損 JSON、非ゼロ終了、警告、権限不足を明示する。ログに写真の全メタデータや個人情報を既定で保存しない。

受け入れには、[テスト計画](testing.md) の技術検証 1〜6、安全性テスト、Windows / macOS の実機確認が必要です。各項目の証拠、使用バージョン、未対応条件を記録するまで、実現可能・対応済みと記載しません。

## Phase 1 の限定範囲

ユーザーの段階的実装指示に従い、SDK のみで JPEG を一時レンダリングし、標準の「書き出し場所」で選んだ保存先へ `test_<元ファイル名>.jpg` としてコピーします。特定フォルダー、元画像と同じフォルダー、標準フォルダー、後で選択、サブフォルダーに対応します。ExifTool、RAW / XMP 探索、テンプレート、C2PA は実装しません。F-09 の衝突時別名化は Phase 7 まで保留し、Phase 1 は同名時にエラーにすることで S-02 を維持します。ユーザーの保存先拡張指示に基づき、明示的に指定したサブフォルダーはレンダリング成功後に作成します。サブフォルダー名は単一の名前とし、親への移動・絶対パス・区切り文字・予約名は拒否します。カタログへの追加・スタック追加は検証版の対象外です。

出力に利用しにくい元ファイル名は置換せず拒否します。元画像不在時も拒否します。製品版の規則を変更するものではありません。実装・検証状態は [Phase 1 記録](phase1-lightroom.md) を参照してください。

## Phase 2 の限定範囲

ユーザーの次フェーズ指示に基づき ExifTool ラッパーと単体診断メニューを追加します。読み取り専用、明示したツールによる検証、既定同梱パスの解決、固定タグ・JSON・内部項目変換、実行時間制限に限定します。Phase 1 の Windows 等の未確認事項は継続します。F-04 の項目単位マージ、F-02 / F-03 のテンプレート・プレビュー、F-08 の削除機能は実装しません。[Phase 2 記録](phase2-exiftool.md)

## Phase 3 の限定範囲

ユーザーの開始指示に基づき `MetadataSourceResolver` と探索単体診断メニューを追加しました。F-05 の探索モード・RAF / DNG の候補選択を実装し、元画像・候補は読み取り専用とします。項目単位の統合（F-04）、本番 UI、全体書き出しとの統合は未実装です。候補が複数、大小文字の stem 差、読取エラーの場合は明示的に失敗します。[Phase 3 記録](phase3-metadata-sources.md)

## Phase 4 の限定範囲

ユーザー指示に基づき F-04 の項目単位統合を純 core として追加しました。普通のテーブルから XMP → RAW → JPG の順に有効値を採用し、無効値・欠落・読取失敗を区別します。診断用の探索・読取・統合手順を追加しますが、書き出しへの統合、メーカー正規化、テンプレート等は実装しません。[Phase 4 記録](phase4-metadata-merge.md)

## Phase 5 の限定範囲

ユーザー指示に基づきメーカー名の正規形と同一比較を実装しました。FUJIFILM の明示別名、TAMRON / SIGMA の大小文字、未知名の trim・ASCII 大小文字正規化に対応します。F-07 の出力省略・設定 UI は未実装で、Phase 6 以降へ残します。[Phase 5 記録](phase5-manufacturers.md)

## Phase 6 の限定範囲

F-06 の 13 トークンと F-07 の意味に基づく LensMaker 省略を純 core として実装しました。解析・展開エラー、欠落一覧・省略一覧を返し、既存統合診断に固定テンプレートの ON/OFF 候補を表示します。F-02 の設定入力、F-03 の書き出し画面プレビュー、F-09 の安全処理・衝突回避・最終保存は後続 Phase に残します。[Phase 6 記録](phase6-templates.md)

## Phase 7 の限定範囲

F-09 の名前整形・衝突候補を純 core に実装しました。禁止文字は置換、制御文字はユーザーの Phase 7 指示に合わせて除去し、空名・予約名・明示した長さ超過を拒否します。既存名とセッション予約名を入力として連番候補を返します。実保存先の探索、OS 比較キーの取得、保存時の再確認、非上書き確定保存、書き出しへの統合は後続 Phase に残します。[Phase 7 記録](phase7-filename-safety.md)

## Phase 8 の限定範囲

F-02 の設定入力、F-03 のサンプルプレビュー、F-05 / F-07 / F-08 の設定 UI とプリセット保存対象を追加しました。出力先は確認済みの標準「書き出し場所」を継続利用します。写真情報がない場合にもエラーにならない明示的サンプルを使用し、実写真の取得は Phase 9 へ残します。C2PA ON は設定を保存できますが、未実装の削除を黙って省略しないため書き出しを拒否します。実命名と保存への統合はまだ行いません。[Phase 8 記録](phase8-export-dialog.md)

### Phase 8 の追加変更（2026-10-09）

ユーザーの指示により Extension トークンを廃止し、拡張子は必ず出力形式から自動付加します。12 個のトークンをクリックでテンプレート末尾へ追加できます。旧プリセットの末尾 `.{Extension}` は UI で移行します。初回 UI の基本動作はユーザー報告済みですが、この追加変更の実機確認は未実施です。

### 追加のトークン整理

ユーザー指示により ISO / FocalLength のトークン・ボタンを廃止しました。現行は 10 トークンです。確認した SDK 14.3 の標準 edit_field ではキャレット位置取得・指定の公開 API が確認できないため、挿入は引き続き末尾追加とし、カーソル位置を推測しません。

## Phase 9 の限定範囲

F-04 / F-05 / F-06 / F-07 / F-09 を実書き出しへ統合しました。JPEG レンダリング結果に実メタデータから生成した名前を付け、標準保存先へコピーします。既存候補は別名化しますが、コピー開始後の失敗は部分ファイルと競合を区別できないため再試行せず失敗にします。元画像を変更・削除しません。ExifTool は未同梱のため開発用絶対パス設定を追加しました。

選択写真から非同期にプレビューを更新できます。実対象・連番・衝突名は保存時に決まり、書き出しは各 rendition の入力を読み直します。C2PA ON は未実装のため拒否します。SDK / OS の非上書き契約・リンク・長いパスは実機ゲートへ残します。[Phase 9 記録](phase9-export-integration.md)

### Phase 9 の衝突番号への統一（2026-10-10）

ユーザー指示により Sequence トークンを廃止しました。現在は 9 トークンです。通常名には番号を付けず、同名時だけ _001 / _002 を付加します。書き出しごとの連番と衝突番号が二重になる挙動を解消します。旧テンプレート末尾の Sequence と隣接する区切り1文字は UI で取り除きます。他の位置に残る場合は未知トークンとして修正を促します。

### トークン表記と FilmSim 表示の変更（2026-10-10）

追加指示により、各トークン値の前後・連続空白を整理し、空白区切りをハイフンにします。英字の大小文字はユーザー回答に従い保持します。FilmSim は指定 Rust コードの既知表示名へ対応付けてから整形します。テンプレートのリテラル・元画像・元 Metadata は変更しません。[対応表](tokens.md#トークン値のハイフン表記2026-10-10)

### 前回設定での出力の安全対策

SDK 生成 JPEG をコピーして二重に残す方式から、検証した生成ファイルだけを非上書きで移動する方式へ変更しました。元 RAW / JPG / XMP は移動しません。生成 JPEG をフォールバック読取元にも使いません。繰り返しの設定更新で最終保存先を失わないようにし、復元不能時は書き出しを拒否します。既存のユーザーファイルや過去の出力は削除しません。

## Phase 10 の限定範囲

F-08をJPEG限定で実装しました。既定OFF、ONは新規の処理済みコピーだけへJUMBF削除を適用し、検証成功後に保存します。全JUMBFが失われることをUIへ表示します。所有・形式・入力不変・対象外バイト保持・再読取を確認できなければ失敗です。64 MiBまでの対応JPEGと通常長のJUMBF APP11パケットに限定し、未対応形式を成功扱いしません。Lightroom / Windows、競合・リンク・別ボリュームは手動ゲートへ残します。[Phase 10](phase10-c2pa.md)

## Phase 11 の限定範囲

現行9トークンと衝突時だけの番号付与を基準に、必須ケースを既存自動テストへ対応付け、所有確認・保持・統合境界の不足を補いました。テストを独立プロセスで実行する開発用補助と手動Integration Testを分離します。製品仕様の追加・変更、ExifTool同梱・ZIP生成は行いません。Windows実機は環境がなく保留で、対応済みとは宣言しません。[Phase 11](phase11-testing.md)
