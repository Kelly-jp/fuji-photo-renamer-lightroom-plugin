# 元名の除外文字列・透かし・後処理

## 対象と処理順

ユーザーの追加指示により`0.10.0.24`で追加しました。

1. 元画像のパスから拡張子を除いた名前を取得する。
2. 指定した除外文字列を、その元名だけから削除する。
3. 削除後の値を`{Original}`として、指定テンプレートを展開する。
4. 禁止文字処理、自動拡張子、衝突時の別名化を行って保存する。
5. C2PA設定に応じた処理・保存に成功した最終JPEGへ、後処理を行う。

元ファイルのパス・内容は変更しません。メタデータ探索は元のパス・stemで行い、除外文字列の設定でRAW/XMPの対応付けを変えません。

## 除外文字列

書き出し設定の「除外文字列を編集…」を押し、「元ファイル名から削除する文字列」に1行1件で入力します。カーソル位置での改行はMacではOption＋Return（ユーザー実機確認済み）、WindowsではCtrl＋J（実機未確認）です。入力後は「編集を完了」を押します。空欄は無変更です。

```text
-DxO_DeepPRIME XD2s_XD
_edited
```

元画像が`DSCF9649-DxO_DeepPRIME XD2s_XD_edited.DNG`なら、削除後の元名は`DSCF9649`です。テンプレート`{Date}_{Camera}_{Original}`の例は`20250612_X-H2S_DSCF9649.jpg`となります。

- 大小文字を区別したリテラル一致です。正規表現やLuaパターンは使いません。
- 各行の前後空白を取り、空行を無視します。CRLF / LF / CRに対応します。
- 同じ文字列の全出現箇所を削除し、削除で新たに一致する箇所ができれば続けて削除します。入力順で処理し、重複パターンはまとめます。
- 空白/タブがハイフンになった元名にも対応します。元の表記とハイフン表記の両方を照合します。
- テンプレートの固定文字、他のメタデータ、自動拡張子、衝突回避番号には適用しません。
- 128件・合計16 KiBまで。制御文字や不正な型はエラーにします。元名処理の上限は64 KiBです。
- 削除後が空でも、`{Original}`を使わないテンプレートは利用できます。使う場合はその写真を失敗として報告します。サンプル名の削除だけで実写真の書き出し全体を禁止しません。

純coreの`FilenameExclusions.lua`が処理し、プレビューと実書き出しに共用します。元名の空白のハイフン化は、その後のTokenResolverで行います。

## 透かし

`showSections`へ公開SDKの`watermarking`を追加し、Lightroom標準の「透かし」欄を表示します。`LR_useWatermark` / `LR_watermarking_id`を上書きせず、標準の選択・プリセット保存・レンダリングに任せます。独自の透かし画像処理やプリセット形式の推測は行いません。

## 後処理

標準の「後処理」欄はLightroom SDK 2.0でカスタムExport Service Providerから削除され、現在はハードディスク向け標準サービスだけの機能です。非公開の設定キーで再現せず、`sectionsForBottomOfDialog`に独自欄を追加しました。ユーザー回答に従い、以下に限定します。

| 設定 | 動作 |
| --- | --- |
| 何もしない（既定） | 外部操作なし |
| Finder / Explorerで保存先を表示 | 保存先フォルダーごとに先頭の最終JPEGを1回表示・選択 |
| 指定したアプリケーションで開く | 保存に成功した最終JPEGのリストを指定アプリへ渡す |

`LrShell.revealInShell(path)` / `LrShell.openFilesInApp(files, appPath)`の構造化引数を使います。シェルコマンドや任意の追加引数は組み立てません。アプリパスを検証してからレンダリングを開始し、実行直前にもアプリと出力ファイルの存在を確認します。SDKのWindows側の引数長分割に任せます。

失敗・スキップした写真、元画像、SDK一時JPEGは渡しません。一部だけ成功した場合は成功分だけを渡します。途中キャンセルでは既存の完成出力を残し、後処理を呼びません。アプリ起動等の失敗は「JPEGは保存済み」と分かる警告にし、保存済み出力を消したり、その写真の保存自体を失敗扱いにしません。外部アプリ内の編集結果・処理完了は追跡しません。

除外文字列・後処理モード・アプリパスはスカラー設定として書き出しプリセットへ保存し、開始時にセッションへ固定します。従来の5項目と合わせて8項目です。

## Returnによる誤書き出し・完了通知の修正（0.10.1.25）

ユーザーから、除外文字列を改行しようとすると書き出しが始まるとの報告がありました。公式Guide PDF p.89のedit_fieldの説明は、ENTER/RETURNが親ダイアログの既定ボタン（Exportダイアログでは書き出し）を呼ぶと明記し、入力完了までそのボタンを無効にするよう案内しています。高さ・折り返しの指定だけでは回避できません。

編集開始/完了ボタンと、末尾へLFを追加する「改行を追加」を追加しました。編集モード中は`LR_cantExportBecause`で書き出しを禁止し、除外欄と改行ボタンは編集中だけ有効にします。編集完了後も設定が不正なら書き出しは禁止したままです。編集モードはプリセットへ保存せず、閉じる/開き直すと解除します。これは誤書き出しの防止策であり、Returnによる改行を実装するものではありません。

正常終了・スキップだけの場合の情報ダイアログを廃止しました。保存失敗、メタデータの警告、後処理失敗、開始前の重大エラーの通知は維持します。進捗と後処理は継続し、完了通知を隠すためにエラーを握りつぶしません。

手動確認では、編集中に書き出しボタンが無効でReturnから書き出されないこと、MacのOption＋Returnで2件以上を入力できること、編集完了で書き出せること、正常終了で情報ダイアログが出ないことを確認してください。

Lua回帰は680件・19ファイル成功（seed=25）。編集開始/完了、改行ボタン、プリセットへ編集状態を残さないこと、不正設定の維持、通常成功/C2PA+後処理/スキップ時の情報通知抑止を追加検証しています。警告・失敗の通知回帰も成功。実キー入力はSDKダブルでは証明できず、Lightroomの手動結果は未確認です。

### 技術検証項目：キャレット位置での改行（2026-10-24）

ユーザー要望は、末尾追加ボタンではなくEnter単独でキャレット位置へ改行することです。末尾追加ボタンではこの要望を満たさないため、ユーザー指示により削除しました。確認したSDK 14.3の公開`LrView.edit_field`プロパティには、Returnの動作変更、キーイベント、キャレット操作のAPIがありません。Guide p.89の既定ボタン無効化でも改行の挿入は保証されません。Enter単独への変更は未実装です。ユーザーがMacでOption＋Returnによる改行を確認し、この操作を案内する方針へ変更しました。

[AppleのField Editor資料](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/TextEditing/Tasks/FieldEditor.html)はOption+Return / Option+Enterで入力位置へ改行できると説明しています。2026-10-24、ユーザーがLightroomの当該入力欄でOption＋Returnによる改行を確認しました。入力欄の説明とREADMEに操作を記載しました。Windowsの改行キーは未検証です。同資料のEnter単独への変更方法はAppKitのネイティブdelegateを必要とし、確認したLightroom公開Lua SDKでは利用できません。非公開プロパティやOSキーフックを推測して追加しません。

改行ボタン削除後のUI境界テストでは、ボタンがなく、Macの改行操作の案内が表示されることを確認します。過去の680件の記録に含まれる改行ボタンのテストは、この案内の検証へ置き換えます。

Windows向けにはCtrl＋Jを入力欄とREADMEへ追記しました。出典は[Adobe CommunityのSDK入力欄に関する開発者報告](https://community.adobe.com/questions-675/windows-new-line-in-text-input-942965)（2016-08-22）です。Adobe公式APIリファレンスによる保証や本プラグインのWindows実機検証とは区別します。Windows環境で編集中にCtrl＋Jがカーソル位置へ改行を挿入し、書き出しを開始しないことを確認する必要があります。

## 設定画面の整理（2026-10-24）

ファイル名トークン9個を1つの横並び行に配置します。除外欄の改行ボタンは置かず、MacのOption＋Return / WindowsのCtrl＋Jと編集完了の操作だけを案内します。編集中の書き出し無効化に関する説明は画面から削除し、誤書き出し防止の制御は維持します。後処理セクションの見出しは「後処理」とします。
