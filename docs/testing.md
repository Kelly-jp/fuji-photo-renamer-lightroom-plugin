# テストと技術検証

## 現在の状態

Phase 1 の最小プラグインと Lua 5.1 の SDK 境界テストを追加しました。Phase 2 の ExifTool 単体連携・診断メニューも追加しました。書き出しとの全体統合は未実装、macOS の基本書き出し、同名時の非上書き、元 RAW / XMP のチェックサム不変はユーザー報告で確認しています。詳細は [Phase 1 の実機確認報告](phase1-lightroom.md#macos-の実機確認報告) を参照してください。以下の残項目は実施計画であり、合格結果ではありません。公式ガイドの Lua 5.1 互換性を確認し、Phase 1 は外部テストフレームワークなしで Lua 5.1 を使用します。製品向けフレームワーク・Lint は未選定です。数値カバレッジ目標は設けず、安全な動作と失敗処理の検証を必須とします。

## テスト層と配置

| 種類 | 配置 | 必須の観点 |
| --- | --- | --- |
| core 単体 | `tests/core/*_test.lua`（予定） | SDK / ExifTool / I/O なし。構文、欠落、型、メーカー、整形、衝突候補。 |
| インフラ結合 | `tests/integration/` | 固定版 ExifTool、探索、JSON、タイムアウト、保存競合、所有確認。 |
| Lightroom 手動 | 結果をこの文書または専用検証記録へ追加 | 設定 UI、プレビュー、複数書き出し、キャンセル、保存先、OS 差。 |

`fixtures/metadata/` には匿名化した XMP / RAW / JPG 読取 JSON と期待結果を置き、機種・形式・ExifTool バージョン・出典・利用許諾を記録します。実画像は合成または配布許可済みの小さな検証用素材だけを追跡します。個人写真や位置情報付き素材は `fixtures/private/` に置き、コミットしません。テストは順序・現在時刻・外部ネットワークに依存させません。

## 振る舞いのテスト

- TemplateParser: 全 13 トークン、リテラル、波括弧エスケープ、不正括弧、未知トークン、パス指定。
- MetadataResolver: 項目別の優先順位、部分 XMP、null・空白・型不正、数値判定、採用元、ReadError と Missing の区別、日時の一貫性。
- ManufacturerNormalizer / TokenResolver: FUJIFILM 別名、異メーカー、未知名、片側欠落、省略 ON/OFF、LensMaker だけのテンプレート、空欄区切り。
- FilenameSanitizer / CollisionResolver: 日本語、禁止文字、予約名、長さ超過、大小文字、拡張子、連番と衝突番号の分離、同一セッションの重複。
- インフラ: RAF / DNG、階層モード、複数 RAW / XMP、オフライン元画像、権限不足、破損 JSON、ツール欠落、非ゼロ終了、警告、キャンセル・タイムアウト。
- 保存: 同時書き込みによる競合、リンク・別名経由の元画像、コピー失敗、確定保存失敗、清掃時の対象制限。
- C2PA: ON/OFF、不在、破損、削除失敗、独立した構造検証、画像・ICC / EXIF / XMP の保持。

安全性テストでは元 RAW / JPG / XMP と既存出力の SHA-256 を前後比較します。カタログは専用テスト用を使い、元画像への書き込みがないことを確認します。セッション所有外のファイルを消さないことも検証します。

## 技術検証項目

**技術検証 1・2 の macOS 基本経路にはユーザー報告がありますが、全項目の成立性は未確認です。** 技術検証 1・2 に関わる Phase 1 の実装、資料確認、境界テスト結果は [Phase 1 記録](phase1-lightroom.md) に分離しました。 公式ページの一般的な機能紹介やタグ表だけで合格にしません。実装開始の指示後に最小限の検証を行い、結果に応じて設計を更新します。

### 1. Export Service Provider の一時レンダリングと任意保存先

- 問い: 一時レンダリング結果を独自名で任意の書き込み可能フォルダへ保存できるか。
- 確認: 公式 SDK の Export Service Provider、レンダリング完了、保存先、成功通知、キャンセルの仕様と同梱サンプル。API 名は確認するまで確定しない。
- 合格条件: 複数 JPEG を独自名で別フォルダへ保存し、上書き禁止・同時衝突・権限不足・キャンセルでも所有外ファイルを変更せず、成功 / 失敗が Classic に正しく表示される。
- 未成立時: adapter と保存方針を再設計する。通常の OS rename が安全な非上書き保存を保証すると推測しない。

### 2. Lightroom API から元画像パスの安全な取得

- 問い: カタログ内の対象写真から元画像の絶対パスを読み取り専用で取得できるか。
- 確認: 公式 SDK の写真メタデータ取得仕様、必要なタスク・アクセス制約、仮想コピー、オフライン、スマートプレビュー、移動済み写真。
- 合格条件: 元 JPG / RAW の正しいパスを得られ、取得不能時は明示的に失敗し、カタログや元画像へ書き込まない。元パスと一時出力の由来を区別できる。
- 未成立時: 対応条件を限定して明記し、安全に取得できない写真を拒否する。

### 3. RAF のメーカー・機種・レンズ・FilmSim 取得

- 問い: ExifTool で RAF から CameraMaker / Camera / LensMaker / Lens / FilmSim を取得できるか。
- 確認: FujiFilm・EXIF・Composite の公式タグ資料と、X-H2S を含む許諾済み複数機種・レンズの実データ。DNG 変換結果も比較する。
- 合格条件: 5 項目の対応タグ、表示変換、欠落条件を特定しフィクスチャ化する。LensMake が記録されない場合など、全ファイルで揃うと主張せず対応範囲と欠落を記録する。
- 未成立時: 欠落項目は仕様どおり表示し、メーカーをカメラから推定しない。必要に応じてサポート範囲を調整する。

### 4. XMP / RAW / JPG の項目別マージ

- 問い: 各形式のタグを共通項目に変換し、項目単位で XMP → RAW → JPG を適用できるか。
- 確認: 同名の異グループタグ、日時の意味、値の型、部分 XMP、複数候補、MakerNotes の維持。
- 合格条件: 3 形式へ意図的に異なる値と欠落を設けたケースで期待値と採用元が一致し、上位の欠落だけが下位へフォールバックする。
- 未成立時: タグ対応表・型変換・候補探索を修正し、データ全体を一括採用する代替にしない。

### 5. 書き出し JPEG の C2PA / JUMBF の安全な削除

- 問い: 新規 JPEG の JUMBF を ExifTool で削除し、元画像と対象外情報を保護できるか。
- 確認: JUMBF 削除コマンド、バックアップ、警告、対象形式、破損入力、リンク経由のパス。別ツールの確認方法も選定する。
- 合格条件: JUMBF が独立検証でも消え、JPEG がデコードでき、画像データ・ピクセルと対象外の ICC / EXIF / XMP が保持され、元画像ハッシュが不変。失敗時は出力未確定。
- 未成立時: 削除機能を利用不可と表示し、ON のまま成功扱いしない。

### 6. Windows / macOS の自己完結した ExifTool 同梱

- 問い: ユーザーの Perl / ExifTool インストールに依存せず起動できるか。
- 確認: Windows の依存ディレクトリ、macOS の同梱ランタイム、CPU、再配布条件、実行権限、署名・隔離属性、日本語パス、読取専用設置先。
- 合格条件: 対象 OS / CPU のクリーン環境で、システム PATH・追加インストール・管理者権限に依存せず、バージョン確認・読取・限定削除が動く。依存とライセンスが配布物に揃う。
- 未成立時: リリースを止め、配布方式または対応範囲の変更を文書化する。システム Perl 利用を自己完結と呼ばない。

## Phase 2 の検証

`lua tests/integration/exiftool_read_test.lua /absolute/path/to/exiftool /absolute/path/to/test-copy.RAF` を macOS の POSIX 対応 Lua 5.1 で実行します。実行ファイルと RAF を明示し、個人写真を自動探索しません。今回の全ケースは 83 件成功し、Phase 1 の 66 件も成功しています。

JSON・タグ変換の単体検証に加え、実プロセスの異常終了・タイムアウト・標準エラー、実 ExifTool による合成 JPEG / XMP と許諾済み RAF の読取を確認しました。RAW の SHA-256 と合成 JPEG / XMP のバイト列不変も確認しました。SDK 境界はテスト用 adapter であり、Lightroom 内・Windows の実機成功とは区別します。取得モデル・公式出典・手動ゲートは [Phase 2 記録](phase2-exiftool.md) を参照してください。
